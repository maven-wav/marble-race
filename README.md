# 구슬 레이스 추첨

사내 행사용 경품 추첨기. **QR 스캔 → 이름 입력 → 구슬 레이스(호스트 스크린) → 각자 폰에서 등수·쿠폰 확인**

| 파일 | 어디서 여나 |
|---|---|
| `index.html` | 참가자 폰 (QR 목적지, `/?r=방코드`) |
| `host.html` | 호스트 노트북 → 빔프로젝터/대형 스크린 |

빌드 없음. 외부 CDN 없음 (QR 은 자체 인코더). Supabase RPC 만 호출합니다.

## 마스터모드

- **쿠폰이 나가는 판**은 방을 만들 때 `🔒 쿠폰 걸기` 를 체크하고 **마스터 비밀번호**를 넣은 방뿐입니다 (`is_prize=true`).
- 마스터 없이 만든 방은 **연습판** — 등수만 나오고 1·2·3등도 아쉬움 멘트를 받습니다.
- 비밀번호는 소스에 없습니다. 호스트가 화면에서 입력하고 `localStorage` 에만 저장됩니다.
- 쿠폰 지급 여부는 서버가 판단합니다 (`marble_my_reward` 의 `kind`). 클라이언트는 등수로 판단하지 않습니다.

## 운영 순서

### 준비 (행사 전날)

1. `host.html` 열기 → 호스트 비밀번호 입력
2. `🔒 쿠폰 걸기` 체크 + 마스터 비밀번호 → **본판** 방 만들기
3. 대기실 하단 `🎁 쿠폰·멘트 설정`
   - 1·2·3등 쿠폰 바코드 이미지 업로드 (각 900KB 이하) + 쿠폰 이름 → 저장
   - 아쉬움 멘트 / 굿딜 링크 확인 (기본값이 들어 있음)
   - 이미지 없는 등수는 당첨자도 아쉬움 멘트를 받으니 3개 다 올렸는지 확인

### 리허설

1. 홈에서 마스터 없이 **연습판** 방을 하나 더 만든다
2. 스태프 몇 명이 QR 로 입장 → `레이스 시작` → `출발!` → 결과·폰 화면 확인
3. 리허설이 끝나면 결과 화면의 `초기화` 로 참가자만 비운다 (연습판은 그냥 두어도 됨)

> 본판 방에서 리허설했다면 반드시 `초기화` 를 누른다. 참가자·결과만 지워지고 쿠폰·멘트는 유지된다.

### 본판 (행사 당일)

1. 행사 5분 전 `host.html` 을 한 번 열어 Supabase 콜드스타트를 깨워둔다
2. 홈 → 최근 방에서 **본판** 방 클릭 → 대기실 (상단에 `🎁 쿠폰 걸린 판` 배지 확인)
3. 스크린에 QR 띄우고 입장 받기 (참여 인원이 2초마다 갱신)
4. `레이스 시작` → 입장 마감, 참가자 폰은 "레이스 진행 중"
5. `출발!` → 약 14초, 1·2·3등 골인 시 정지 → 시상대 화면
6. 참가자 폰에 등수가 뜨고 `🎁 결과 확인` 으로 쿠폰(1·2·3등) / 할인 링크(그 외) 확인

### 사고 대응

- **호스트 화면이 레이스 중 꺼짐**: `host.html` 다시 열고 최근 방에서 그 방 클릭 → 마감된 명단 그대로 다시 달림
- **결과 전송 실패**: 결과 화면에 `결과 다시 보내기` 버튼이 뜸
- **참가자가 QR 을 못 찍음**: 대기실에 적힌 주소로 들어가 방 코드 6자리 직접 입력
- **참가자 폰이 이전 방에 붙어 있음**: `다른 방으로 입장` 버튼, 또는 새 QR 을 찍으면 자동으로 새 방으로 들어감

## 등수 규칙

1·2·3등은 골인 순서, 4등부터는 멈춘 순간 얼마나 멀리 갔는지 순서. 200명이면 1~200등이 빠짐없이 나옵니다.
이름이 겹치면 서버가 `maven` → `maven2` 로 붙여줍니다 (방마다 독립).

## 부하

참가자 1명당 2.5초에 폴링 1건 → 200명 기준 초당 80건. Supabase 무료 티어에서 충분합니다. Realtime 은 쓰지 않습니다.
레이스는 호스트 화면에서만 돌고 폰에는 중계하지 않습니다.

## 서버

Supabase `marble` 스키마 (`config` / `rooms` / `players` / `prizes`). 테이블은 Data API 에 노출되지 않으며 `public.marble_*` RPC 로만 접근합니다.
비밀번호·기본 멘트 변경은 Supabase SQL Editor 에서 `marble.config` 를 수정합니다.
