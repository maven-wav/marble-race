# 구슬 레이스 추첨

사내 행사용 경품 추첨기. **QR 스캔 → 이름 입력 → 구슬 레이스(호스트 스크린) → 각자 폰에서 등수·쿠폰 확인**

한 페이지(`index.html`)로 돌아갑니다.

| 역할 | 어떻게 |
|---|---|
| 호스트 | 사이트 열기 → 이름 → **방 만들기** → 방 코드·QR 이 뜸 → 스크린에 띄우기 → **시작하기**. 방장도 구슬로 같이 달린다 (결과 화면의 `🎁 방장 결과 보기`) |
| 참가자 | QR 스캔(`/?r=방코드`) 또는 방 코드 입력 → 이름 → **참가** |

빌드 없음. 외부 라이브러리 없음 (QR 은 자체 인코더, Pretendard 서체 링크 하나만 예외). Supabase RPC 만 호출합니다.

## 상품 모드 (PIN)

- 그냥 **방 만들기** 로 만든 방은 **연습판** — 등수만 나오고 1·2·3등도 아쉬움 멘트를 받습니다.
- 입구 화면의 **🎲 주사위를 7번 연속 탭** (탭 사이 3초 이내) → **호스트 모드** 모달. 방장 이름은 `메이븐` 고정, `연습판 만들기` 버튼과 **화면 숫자 키패드**(PIN) + `🎁 만들기`. PIN 이 맞는 방만 `is_prize=true` 가 되어 실제 쿠폰이 나갑니다.
- 호스트 모드는 **타이핑이 전혀 없습니다** — 웹 텍스트 입력이 막힌 회사 노트북에서도 방을 만들 수 있게 한 것. 쿠폰 등록(라벨 입력)은 타이핑이 필요하니 **미리 다른 기기에서 한 번** 해두면 기본값으로 자동 복사됩니다.
- PIN 은 소스에 없습니다. 쿠폰 지급 여부는 서버가 판단합니다 (`marble_my_reward` 의 `kind`).
- 방 생성·시작·결과 전송에 쓰는 호스트 키는 클라이언트에 들어 있습니다 (누구나 연습판은 만들 수 있음). 상품은 PIN 으로 따로 잠깁니다.

## 운영 순서

### 준비 (행사 전날)

1. 사이트 열기 → **🎲 주사위 7번 탭** → 키패드로 PIN → `🎁 만들기` → **본판** 방 생성 (이름 입력 없음)
2. 대기실 하단 `🎁 쿠폰 등록` (상품 방에만 보임)
   - 1·2·3등 쿠폰 바코드 이미지 업로드 (각 900KB 이하) + 쿠폰 이름 → 저장
   - 아쉬움 멘트 / 굿딜 링크 확인 (기본값이 들어 있음)
   - 이미지 없는 등수는 당첨자도 아쉬움 멘트를 받으니 3개 다 올렸는지 확인
   - **한 번 등록하면 서버에 기본값으로 남아** 이후 만드는 상품 방마다 자동으로 들어간다 (`marble.prize_defaults`). 멘트·링크도 마찬가지

### 리허설

1. **나가기** 후 그냥 **방 만들기** 로 **연습판** 방을 하나 더 만든다
2. 스태프 몇 명이 QR 로 입장 → `레이스 시작` → `출발!` → 결과·폰 화면 확인
3. 리허설이 끝나면 결과 화면의 `초기화` 로 참가자만 비운다 (연습판은 그냥 두어도 됨)

> 본판 방에서 리허설했다면 반드시 `초기화` 를 누른다. 참가자·결과만 지워지고 쿠폰·멘트는 유지된다.

### 본판 (행사 당일)

1. 행사 5분 전 사이트를 한 번 열어 Supabase 콜드스타트를 깨워둔다
2. 호스트 노트북은 마지막으로 연 방을 기억한다 — 본판 방을 만든 브라우저로 다시 열면 바로 그 방 대기실 (`상품이 있어요` 배지 확인)
3. 스크린에 QR 띄우고 입장 받기 (참여 인원이 2초마다 갱신)
4. `시작하기` → 입장 마감, 참가자 폰은 "레이스 진행 중"
5. `출발!` → 약 14초, 1·2·3등 골인 시 정지 → 시상대 화면
6. 참가자 폰에 등수가 뜨고, 1·2·3등은 `🎁 상품 받기` → 바코드, 그 외는 `플링크 7% 할인 받기` 가 바로 굿딜 링크(새 탭)

### 사고 대응

- **호스트 화면이 레이스 중 꺼짐**: 같은 브라우저로 사이트를 다시 열면 그 방으로 돌아가고, 마감된 명단 그대로 다시 달림
- **결과 전송 실패**: 결과 화면에 `결과 다시 보내기` 버튼이 뜸
- **참가자가 QR 을 못 찍음**: 대기실에 적힌 주소로 들어가 방 코드 6자리 직접 입력
- **참가자가 나갔다 다시 들어옴**: 방 코드별로 참가 세션을 기억하므로 같은 방에 다시 들어오면 기존 참가자로 복귀한다 (중복 참가 안 됨). 다른 방 QR 을 찍으면 그 방으로 넘어간다
- **호스트가 나가기를 누름**: 확인 후 참가자를 전부 지우고 나간다 (방 폭파). 참가자 폰은 몇 초 안에 입구로 돌아간다. 새 방을 만들고 QR 을 다시 띄우면 된다 (쿠폰은 방마다 다시 등록)

## 방 토큰 (보안)

호스트 키는 소스에 들어 있어 누구나 알 수 있으므로, 방을 건드리는 모든 호스트 RPC 는 **방을 만들 때 서버가 그 기기에만 준 토큰**을 함께 요구한다 (`marble.rooms.host_token`).
다른 사람이 호스트 키만으로 남의 방을 조회하거나(참가자 id 유출 → 쿠폰 탈취), 순위를 조작하거나, 초기화할 수 없다.
토큰은 호스트 브라우저의 `localStorage` 에만 있으니 **본판은 반드시 행사에 쓸 그 노트북·브라우저로 만든다.**

## 스타벅스 이미지

상품 방 배지(`상품이 있어요`)에 `starbucks.svg` 를 쓴다. 저장소 루트에 파일을 넣고 push 하면 되고, 없으면 ☕ 로 표시된다.

## 화면 꺼짐 방지

참가·방 만들기 버튼을 누르는 순간 Screen Wake Lock 을 걸어 폰 화면이 자동으로 꺼지지 않게 한다 (Android Chrome, iOS Safari 16.4+).
다른 앱에 갔다 오면 다시 건다. 카카오톡 같은 인앱 브라우저에서 안 먹으면 기본 브라우저(Safari/Chrome)로 열라고 안내.

## 개발자 모드 (인원 테스트)

호스트 대기실에서 **방 코드를 5번 연속 탭** → 테스트 참가자 N명(한 번에 최대 600)을 서버에 실제로 입장시킨다. 서버 자체에는 인원 제한이 없다. 폰 여러 대 없이 200명 레이스를 돌려볼 때 사용. 끝나면 `초기화` 또는 `나가기` 로 비운다.

## 등수 규칙

1·2·3등은 골인 순서, 4등부터는 멈춘 순간 얼마나 멀리 갔는지 순서. 200명이면 1~200등이 빠짐없이 나옵니다.
이름이 겹치면 서버가 `maven` → `maven2` 로 붙여줍니다 (방마다 독립).

## 부하

참가자 1명당 2.5초에 폴링 1건 → 200명 기준 초당 80건. Supabase 무료 티어에서 충분합니다. Realtime 은 쓰지 않습니다.
레이스는 호스트 화면에서만 돌고 폰에는 중계하지 않습니다.

## 서버

Supabase `marble` 스키마 (`config` / `rooms` / `players` / `prizes`). 테이블은 Data API 에 노출되지 않으며 `public.marble_*` RPC 로만 접근합니다.
비밀번호·기본 멘트 변경은 Supabase SQL Editor 에서 `marble.config` 를 수정합니다.
